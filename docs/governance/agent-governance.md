# Agent 文档工程指南

本指南用于创建和改造项目文档。执行约束由 [通用工作标准](templates/standards.md) 定义，本指南负责文档职责、标准承接和项目适配。

## 改造现有项目

1. 从项目入口读取当前规则、契约和工作状态，核对源码与实际验证结果。
2. 列出缺失、冲突、过期和重复维护的内容，明确每类事实的所有者。
3. 保留有效文档，修正职责与路由。涉及批量移动或不可恢复操作时，先建立操作协议。
4. 按下文承接标准，补齐真正需要的模板。现有明确约束先保留，冲突交给人裁定。
5. 验证新的 Agent 能从入口确定范围、找到契约并开始第一个任务。

不按文件数量或代码行数直接套用整套模板。没有独立决策价值的文件不建，已有文档能承担的职责不另建。

## 标准权威版本与项目承接

```text
agentic-work-infra
  docs/governance/templates/standards.md  通用标准的权威版本
           ↓ 固定版本副本
目标项目
  docs/STANDARDS.md            项目采用的通用标准
  AGENTS.md                   项目边界和路由
  模块契约或模块 AGENTS.md    模块自己的补充约束
  docs/LESSONS.md              失败证据与规则反馈
```

- **权威版本仓库**：本仓 `docs/STANDARDS.md` 指向标准权威版本，每类事实只在一处维护。
- **目标项目**：从明确的已提交版本复制标准，在副本头部注明源仓库、完整 commit 和源文件路径。标注置于标准正文之外，正文保持与该版本一致。副本由项目维护，Agent 不私改、删改或按规模复制通用规则；不适用条款按标准中的适用性处理。
- **项目自治**：项目和模块在自己的边界文档中补充约束，不削弱通用标准的授权、数据和证据边界。冲突先显式报告并由人裁定，不能以局部规则默默覆盖。
- **规则反馈**：项目经验在 LESSONS 中提出，通用规则经审议后晋升到权威版本，场景约束留在项目。单个项目命令、私有路径和宿主配置不晋升为通用规则。
- **显式升级**：权威版本更新不会自动改变项目。项目采用新版本时核对规则差异、已有约束和验证要求，更新副本与来源标注，并在提交或评审中记录采用版本及验证结果。回退时恢复上一份已采用副本和对应标注。

既有项目如果已经修改过标准副本，先列出与原版本的差异，区分通用改进和项目约束，经裁定后晋升。不用新的副本静默覆盖现有规则。

## 文档职责与更新条件

| 文档 | 回答的问题 | 更新条件 | 模板 |
| --- | --- | --- | --- |
| `README.md` | 项目是什么，如何开始 | 定位、安装方式或公开命令改变 | [readme.md](templates/readme.md) |
| `AGENTS.md` | Agent 的范围和读取入口 | 稳定边界、适用规则或路由改变 | [agents.md](templates/agents.md) |
| `docs/STANDARDS.md` | 通用执行约束 | 显式采用经审议的新版本 | [standards.md](templates/standards.md) |
| `docs/ARCHITECTURE.md` 或 `docs/architecture/` | 职责、依赖、接口、数据所有权 | 文档化的架构契约改变 | [architecture.md](templates/architecture.md) |
| `docs/DESIGN.md` | 视觉语言和组件样式 | 品牌、排版或视觉规范改变 | [design.md](templates/design.md) |
| `docs/HANDOFF.md` | 当前在哪里，下一步做什么 | 优先级、阻塞或接手动作改变 | [handoff.md](templates/handoff.md) |
| `docs/LESSONS.md` | 失败说明了什么，规则是否需要改 | 有新的失败证据或审议结论 | [lessons.md](templates/lessons.md) |
| `docs/DEPLOYMENT.md` | 如何生效、核验和回退 | 部署流程或验收要求改变 | [deployment.md](templates/deployment.md) |
| `docs/architecture/adr/` | 为什么接受某个架构决策 | 新决策形成；旧决策被取代时标明关系 | [adr.md](templates/adr.md) |

独立项目或需要单独接手的仓库需要 README、AGENTS 和采用的标准。mono-repo 的模块、Skill 和 track 默认继承父级入口与标准，只在有独立契约、生命周期或接手节奏时添加自己的文件。其余文档按决策需要添加，不建空目录。架构文档：小项目用 `docs/ARCHITECTURE.md` 单文件，大项目升级为 `docs/architecture/` 目录管理。DESIGN 只承担视觉规范。部署文档必须唯一：统一到 `docs/DEPLOYMENT.md`，项目已有其他部署文档时对齐到此规范。

稳定文档按契约变化更新，不按周、不按每次代码修改更新。README 不放当前阶段、测试数量、待办或部署哈希；它提供稳定命令入口，命令实现归脚本和配置维护。架构文档以模块边界和公共接口为锚点，不抄录容易变化的私有实现。

HANDOFF 和 LESSONS 承担需要持续维护的状态。HANDOFF 在交接条件改变时更新，不充当完成日志。验收结果进入可回查的提交、评审或版本报告；历史结果保持对应版本，发现错误时显式更正，不改写成当前结果。

## 入口和路由

根 `AGENTS.md` 是 Agent 的进入入口，记录项目定位、稳定边界、验证入口和按任务读取的文件。一般控制在 50 行左右，复杂项目不超过 100 行；先消除重复职责，再考虑拆分。

- 开始任务：入口 → 采用的标准 → 当前工作 → 相关模块契约。
- 调整视觉：读取 docs/DESIGN.md。
- 修改接口、数据或职责：读取对应架构或协议文档。
- 部署：读取 docs/DEPLOYMENT.md。
- 临时授权和本次任务变量：来自人的任务指令，不固化进稳定入口。

验证命令的实际定义归脚本或配置。README 解释稳定用法，AGENTS 指向任务所需验证入口。命令内部改变而公开入口不变时，无需重写入口文档。

索引只负责路由，不维护第二份能力清单或阶段摘要。被索引文件的内容更新时，索引通常无需更新；只有入口或路径改变才更新路由。

## Mono-repo 适配

同一仓库采用一份通用标准。每类事实由负责它的模块维护，其他地方通过链接引用。

**仓库层**负责项目集合、允许的依赖方向、跨模块验证和共同部署约束。实际依赖从包配置或构建配置核对，架构文档解释边界与理由。

**模块层**负责自己的产品契约、公共 API、数据格式和局部验证。README 提供稳定使用入口；有独立约束时才添加模块 AGENTS，不给每个模块复制整套治理文档。共享包定义能力契约，消费者定义业务使用方式。

模块规则在声明范围内继承仓库和通用约束。跨模块任务读取所有受影响模块的契约；不能仅凭最近目录的文件扩大写入范围，也不能假设每个 Agent 宿主会自动加载嵌套规则。根入口必须能明确路由到相关模块。

当前工作默认集中在一份根 HANDOFF，按模块记录。确有独立交接节奏时可设模块 HANDOFF，根只链接，不重复摘要。LESSONS 默认集中记录，并注明适用范围；只有独立维护需要成立时才拆分。

验证范围遵循标准的 [验证要求](templates/standards.md#验证)：覆盖改变的模块及受影响消费者，公共配置、影响不清或正式发布时扩大范围。局部检查与仓库完整检查各有明确入口，CI 调用相同入口，不另写一套规则。

## 多 Agent 协作项目的文档组织

**所有项目的基础文档**：
- `AGENTS.md` — 项目入口，声明协作模式和读取路径
- `docs/STANDARDS.md` — 从 agentic-work-infra 复制的执行约束

**三层协作额外需要**：
- `docs/ROLES.md` — 定义 Architect/Worker/Reviewer 角色和会话名
- `docs/HANDOFF.md` — Architect 维护当前状态和任务分配

**按需添加**（所有模式）：
- `docs/LESSONS.md` — 失败经验，审议后晋升到规则
- `docs/ARCHITECTURE.md` 或 `docs/architecture/` — 架构文档（小项目单文件，大项目目录管理）
- `docs/DESIGN.md` — 视觉规范（前端项目）
- `docs/DEPLOYMENT.md` — 部署规范（需要部署的项目）

三层协作项目的 AGENTS.md 示例：
```markdown
## 协作模式
本项目采用三层协作模式，角色定义见 [docs/ROLES.md](docs/ROLES.md)

## 优先读取
1. [角色定义](docs/ROLES.md)
2. [通用工作标准](docs/STANDARDS.md)
3. [当前状态](docs/HANDOFF.md)
```

双 Agent 项目可以在 AGENTS.md 中简单说明 Architect/Worker 分工，不需要独立的 ROLES.md 和 HANDOFF.md。

单 Agent 项目只需要 AGENTS.md 指向 docs/STANDARDS.md 即可。

## 规则如何演化

LESSONS 记录候选规则、具体证据和适用范围。相同问题重复出现三次触发审议，晋升仍需判断根因、严重程度、反例和维护成本；单次严重问题也可以触发审议。

人确认后按所有者更新：通用规则晋升到标准权威版本，项目约束晋升到项目边界，模块契约晋升到模块。LESSONS 保留指向正式规则的引用，不继续维护另一份正文。目标项目在显式采用新版本前仍执行原版本。

## 模板使用与验收

新项目先实例化 agents、readme 和 standards，再按上表选择必要文档。删除无用字段和示例，填入实际命令与范围。模板中的填空字段只属于模板，不进入正式项目文档。

改造现有项目优先保持有效路径。文件移动时同一变更修正引用；历史研究和完成的会话指令退出默认读取路径，保留来源与版本。

文档工程验收检查：

- Agent 能找到适用标准、当前工作和相关契约，并开始第一个任务。
- 每类规则和状态有明确所有者，引用能解析，模板实例化后无占位字段。
- 稳定入口不包含当前阶段、测试计数或机器临时状态。
- 普通实现修改无需同步多份摘要，契约变化只更新所属文档和受影响引用。
- mono-repo 的共享规则、模块边界和跨模块验证范围明确。

验证执行方式与未覆盖项按通用标准记录。指南和模板的一致性也属于验收范围。
