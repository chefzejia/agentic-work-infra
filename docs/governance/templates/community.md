## 社区 PR 审查协议

本项目通过 Agent 审查和合并社区 PR。以下协议保护用户安全并控制审查成本。

### 安全优先检查

**在运行 PR 代码或进行完整审查前**，检查 diff 是否触碰以下任何一项：

- 修改 CI/CD 配置（`.github/`、`.gitlab-ci.yml`、`.drone.yml` 等）
- 修改发布、部署脚本、Dockerfile、构建配置
- 添加网络地址、上传、遥测，或向新位置发送凭证、token、cookie
- 读写凭证文件、密钥链、Agent 配置（目标之外）
- 添加依赖、`replace` 指令、install 脚本、二进制文件、压缩/编码 blob、动态代码生成
- 添加联盟链接、转售商地址、已被维护者移除的供应商

**触发任何一条 → 停止审查，标记给人类维护者，说明触发行号。**

不在有真实账户的机器上运行未经人类清除的此类 PR。

### 可直接关闭（无需完整审查）

以下 PR 附简短理由关闭，不运行代码：

- 修改维护者已裁定的设计决策（参考项目 `docs/STANDARDS.md` 或 `docs/LESSONS.md` 中"不采纳"的内容）
- 重新提交已因理念拒绝的 PR，且没有新论据回应拒绝理由
- 几秒内批量开启的多个近似重复 PR

### 阻止贡献者

当作者满足以下**任一条件**时，提议加入阻止名单：

1. 有 3 个或以上 PR 被维护者关闭为低质量（错误、未测试、无关、机器生成填充），且合并率 < 30%
2. 在明确拒绝后仍重新提交同一 PR，达 2 次
3. 存在欺骗行为：在 PR 声明目标之外隐藏修改、伪造测试或验证、故意触发"安全优先检查"条款
4. 机器批量开启低质量 PR（1 分钟内多个，且符合条款 1）
5. 在被告知不可后，重新添加已移除的供应商、中继或广告

**Agent 只提议，不决定**。将证据（PR 号、日期、问题描述）写给维护者，由人类裁定。

被阻止作者的新 PR/Issue 关闭并回复："Thanks — this account's contributions aren't accepted in this repository." 不再争论。

### 额外小心审查的作者

维护者选择不阻止但需加强审查的作者：

- 逐行读取 diff 全部内容，不只是描述提及的部分
- 对比修改文件与声明目标，超出目标即关闭
- 完整执行"安全优先检查"，即使 PR 看起来只是拼写修正
- 在当前 `main` 上亲自运行，不依赖 PR 声明或其 CI
- 同一 tick 内不合并，使用 `--match-head-commit`
- 重复已关闭 PR 时附上首次链接并关闭

| --- | --- |
| （按需添加） | （PR 号、问题描述、处理方式） |

### 观察中的作者

有用但持续缺失相同检查项的贡献者。不属于阻止或额外小心，但审查时重点检查已知缺陷。

## Issue 管理协议

### Issue 分类

Agent 首次响应 Issue 时进行分类：

- **Bug 报告**：需要复现步骤、环境信息、预期/实际行为
- **功能请求**：需要用例、替代方案、愿意贡献吗
- **问题求助**：引导到讨论区或文档
- **讨论**：标记为 discussion，移至 Discussions（如平台支持）

### 不完整 Issue 的处理

缺少关键信息时，Agent 回复模板请求补充，标记 `needs-info`，7 天无响应自动关闭并说明原因。

### 重复 Issue

搜索已有 Issue，找到重复时关闭并链接到原 Issue："Duplicate of #123"。

### Issue 关闭条件

- 问题已在某个 commit/PR 中修复 → 关闭并链接
- 按设计工作，不是 Bug → 解释并标记 `wontfix`
- 功能请求不符合项目方向 → 解释并标记 `wontfix`
- 无法复现，提供方未响应 → 7 天后关闭

**保持 Issue 开启直到报告者确认解决**。报告者说没解决时重新打开。

## Agent 审查者职责边界

### Agent 可以做

- 执行上述安全检查和分类
- 审查代码质量、测试覆盖、风格一致性
- 运行测试和验证
- 合并通过审查的 PR
- 关闭明确违反协议的 PR/Issue

### Agent 必须升级给人类

- 触发"安全优先检查"的 PR
- 提议阻止某作者（提供证据，等待裁定）
- 架构决策冲突
- 需要改变项目方向或优先级的功能请求
- 任何不确定是否应该合并的 PR

### Agent 不可以做

- 未经人类清除而运行高风险 PR
- 自行决定阻止作者
- 修改已被维护者裁定的设计决策
- 代表项目做出政策承诺

## 维护建议

### 定期审查（每月或每季度）

- 检查"观察中的作者"是否改进或需升级
- 检查"额外小心审查的作者"是否可移除
- 更新"安全优先检查"清单（新的风险类型）
- 审查关闭统计，避免误关有价值贡献

### 透明化原则

- 本文档公开在仓库中，所有贡献者可见
- 关闭 PR/Issue 时说明理由和参考条款
- 阻止决定在本文档中记录证据（去隐私化）

### 人性化原则

- 对新手友好：首次低质量 PR 提供改进建议，不直接关闭
- 假定善意：除非明确欺骗，否则先沟通
- 尊重贡献者时间：快速响应，清晰说明期望

---

## 文档维护

- 本协议适用于 Agent 审查者，也适用于人类审查者作为参考
- 安全检查清单随威胁演化更新
- 作者列表按需更新，不保留历史已解决的案例
- 协议变更需人类维护者批准，Agent 不自行修改
