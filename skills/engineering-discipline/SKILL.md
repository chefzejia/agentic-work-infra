# 工程与验证纪律 Skill

## 核心原则

1. **契约规定目标，源码与运行结果说明当前事实**：两者不一致时定位根因，绝不通过篡改契约或放宽测试把缺陷伪装成正确。
2. **共同可观测，不维护隐式状态**：判断、修改和验证证据必须对人直接可见，不在不透明缓存或临时脚本里藏匿状态。
3. **找根因，不打表层补丁**：连续两次对同一症状打局部补丁仍未解决，说明根因未找到，必须停下来重新推演。

## 工具选择梯度（永远选最轻够用的一级）

按精确性、可重复性和调用成本由轻到重选择，不盲目动用重型工具：

```text
L1 结构化接口：服务自身的 API / SDK / 原生结构化工具
L2 确定性 CLI：git、curl、构建工具、测试运行器、编译器等命令行
L3 脚本化驱动：Playwright（网页 DOM/网络交互）、原生应用自动化脚本
L4 像素级驱动：Computer Use（仅用于覆盖无任何 API/CLI 的纯 GUI 表面）
```

- **跳级必须显式说明理由**（如“目标依赖真实浏览器布局计算，CLI 无法覆盖”）。
- **断言“环境不具备某能力”前必须先实测**，区分“未配置”与“宿主不支持”，不静默跳过验证。

## 子 Agent 派发纪律（Sub-agent Dispatch）

子 Agent 不是免费的多线程，每次派发都会产生**冷启动重复阅读税、指令序列化损耗与共享工作区踩踏风险**。严禁为了“表演式并发”把小功能拆给多个子 Agent：

1. **双层路由与默认委派边界（Fast Path = `0` vs Slow Path 必派 Worker）**：
   - **Fast Path（主会话直办 = `0`）**：≤ 5 步工具调用可完成的局部微调、少量文件读取或上游共享契约（如 `schema.py`）的冻结，主 Agent 亲自完成，避免子 Agent 冷启动重复阅读税。
   - **Slow Path（完整功能实现/重度审查 = 必派隔离 Worker/Tester）**：DeepSeek《Super-agent 设计探索》实测表明，若不加硬约束，主会话极易陷入“觉得活小自己顺手全干了”的陷阱，导致主窗口阻塞、上下文被底层实现细节填满。因此，一旦任务属于**完整业务模块实现、跨多文件重构或独立测试验收**，主会话必须充当纯 Router/Brain（只分派不干活，仅 Inline 摘要、将细节 Spill 到子会话），默认在幕后调度 Worker 与 Tester 闭环。
2. **写操作（Write / Edit）并发上限 = `1`（共享工作区严禁多写）**：
   - 在同一个本地工作区（共享 Working Tree）内，**同一时刻最多只允许 `1` 个执行写操作或跑构建/测试的 Agent**（要么主 Agent 自己写，要么只派 1 个写操作子 Agent）。严禁同时派多个子 Agent 改不同小功能。
   - 仅当满足 **① 写文件集 100% 物理正交**（无共享入口、路由或配置文件）、**② 共享接口/Schema 已由主 Agent 提前冻结落盘**、且 **③ 具备独立工作树（Worktree）隔离**时，才允许跨模块并行写，且单批并发上限 **`≤ 3` 个**。
3. **只读操作（Read / Explore / Audit）并发上限 = `2 ~ 4`（按正交子系统拆）**：
   - 只读调研或审查无文件锁冲突，可并发扇出，但必须按**正交子系统或独立审查维度**拆分（单批 **`2 ~ 4` 个**封顶），禁止按零碎单文件拆出大批子 Agent。

## 变更与防御式编码纪律（10 条铁律）

1. **精确覆盖范围**：说清哪些情况变了、哪些相邻情况没变，不同性质的错误不混作同一种兜底。
2. **到达所有同类位置（Reach Every Sibling）**：修一处缺陷后全局检索同构模式（同类调用点、子命令、守卫），在同一变更内一并修复。
3. **重推导下游依赖**：改了公式、数据结构、布局或时序，必须找出所有假设旧语义的调用方、缓存和测试并重新验证。
4. **读失败即未知（Fail-closed）**：读取、解析或校验失败时，结果是“未知”而非“空/无/相等”；安全与权限守卫遇到读取失败必须拒绝放行。
5. **预览零副作用**：`dry-run`、`plan`、`preview` 等只读操作绝不写入任何持久或临时状态。
6. **错误分类窄化**：一个错误码或异常标记只对应它精确描述的那一种失败，不吞掉未知异常。
7. **外部系统取值溯源**：对接外部系统或协议时，字段类型与取值从该系统的官方契约或二进制实测中获取，不凭字段名臆测。
8. **时序不承载正确性（Timing Does Not Carry Correctness）**：正确性必须来自显式的调用顺序或状态机，**严禁用 `setTimeout(..., 0)`、`queueMicrotask` 或固定 `sleep` 碰运气等待渲染/异步状态就绪**。
9. **可选输入显式声明双分支（No `?.` Fallback Chains）**：严禁堆叠 `a?.b?.c?.d ?? fallback` 掩盖契约缺失；可选参数必须在接口契约中同时规定“存在时”与“缺省时”的确定性行为。
10. **单值单语义（One Value States One Fact）**：“尚未查询（`unknown`）”、“查询结果为空（`empty`）”与“具体值（`value`）”是三种不同事实，必须用可辨识联合类型（Discriminated Union）或显式枚举区分，严禁用单一 `null / undefined` 混代多种语义。

## 代码注释与文档去噪铁律（No Reasoning Transcripts）

1. **只写契约，不写心路历程**：注释、JSDoc 和文档只陈述**类型签名与代码结构无法表达的契约**（前置/后置条件、不变量、所有权、并发锁序、反直觉失败行为）。**严禁把调试推理过程（“之前用 X 会报错所以改成 Y”）、步骤旁白或复盘流水账写进代码注释或长期文档。**
2. **已落地文档一律用现在时（Present-Tense Only）**：功能或决策合入后，文档只描述**系统当前如何工作**；严禁残留 `should`、未来计划、迁移待办清单或 `"（已实现！）"` 等易腐状态词。
3. **内部重构零文档税**：文档只链接源码文件与符号名，不抄录常变的实现细节；只要对外职责、状态流转和失败契约未变，内部重构无需修改文档。

## 调试纪律（三面互证法）

排查问题时，三个观察面必须独立校验，不依赖单一信号：
- **行动面**：通过正式入口推进（公开 API、CLI、真实 UI），不为凑测试而在生产代码里开后门。
- **观察面**：用只读证据判断系统内部发生了什么（日志、进程状态、数据库只读查询），观察动作本身不制造新状态。
- **判定面**：对照业务契约检查最终结果，**进程退出码为 0、HTTP 200 或日志无报错不能单独作为成功证据**。

**根因定位公式**（先保留失败现场，写出可证伪的结论再改代码）：
> 当 `<触发条件>` 发生时，`<责任模块>` 因为 `<错误机制>` 未能完成 `<应尽职责>`，导致用户观测到 `<表面症状>`。

## 验证分层、架构守卫单测与测试隔离

验证按层次递进，下层通过不能替代上层验收：

```text
静态检查（Typecheck / Lint） → 单元测试 & 架构守卫单测（Guard Tests） → 集成测试（真实依赖/持久化） → E2E 验收（正式入口 + 真实数据流）
```

- **架构规则优先写成守卫单测（Guard Tests over Prose Warnings）**：凡能用代码静态扫描或反射锁死的架构红线（如“核心包禁止 import 插件”、“禁止裸调 `exec.Command`”、“禁止残留 Svelte 4 `$:` 语法”、“配置项与 Schema 必须同步”），**必须直接写成 `tests/` 下的守卫单测随测试套件自动执行**，绝不只写在 Markdown 里靠 Agent 自觉。
- **缺陷修复必配“还原即红”测试**：修复 Bug 的测试必须在退回旧代码时真实失败（`FAIL`），且测试输入优先使用真实故障现场字节而非手造的理想化样本。
- **工程自检（Worker）与模拟真实用户验收（Tester）的职责切分**：
  - **代码单测与构建门禁归实现者（Worker）**：类型检查、单元测试、架构守卫单测与构建打包是写代码的 Agent 交卷前必须跑通的工程底线（且严禁编写 `vm.runInContext` 等脱离真实运行环境的假 UI 测试充数）。
  - **独立验收（Tester）必须按产品形态模拟真实用户**：调试与验收方式由产品形态决定——CLI 工具按用户视角执行真实命令，Web/桌面客户端像不懂技术的人类用户一样点按交互并**每一步截屏用视觉肉眼审视画面**（排版美感、图文截断、弹出位置、文案通顺度），绝不能把“跑通代码测试脚本返回 `ok: true`”当成用户体验合格。
- **测试沙盒直接复用、零防御内耗**：
  - 单测在临时目录运行，不触碰宿主机真实用户数据；
  - 项目的专用测试沙盒（如仓库内已列入 `.gitignore` 的 `.dev-vault/` 或 `.tmp/`）本来就是供 Agent 自由操作、读写和重置的游乐场——直接打开使用即可，**严禁为了“证明沙盒隔离”而去编写快照备份、进程树扫描、文件哈希比对等过度防御代码，也严禁在仓库根目录自创未忽略的临时文件夹**。
- **测试替身（Mock / Stub）必须声明证明范围**：替身只能证明受控条件下的状态流转与分支逻辑，**绝不能宣称真实外部依赖或端到端业务旅程已跑通**。
- **链式命令防吞错**：管道验证必须开启 `set -o pipefail`，防止前置测试失败被后续命令掩盖。

## 架构加减法与 AI-Native 选型剃刀（Eliminate Human-Bandwidth Compromises）

**第一性原理**：过去许多主流框架、黑盒库与中间层，并非物理或数学上的最优解，而是为了迁就“人类手写代码慢、记忆带宽低、跨语言学习贵、算几何坐标痛苦”而发明的**人类带宽妥协层（Compromise Layers）**（详细推导与参考栈见 `docs/core/ai-native-first-principles.md`）。当 AI 将语法转译、几何计算与样板编写成本压近于 $0$ 时，每次技术选型、引入依赖或设计方案前，遵循四条极简准则：

1. **第一性原理三问（每次引入框架/库/抽象前必问）**：
   - **质疑妥协性**：这个方案之所以流行，是因为它在物理性能与最终体验上真的最优，还是仅仅因为过去人类手写太慢而找的“拐杖”？
   - **探寻原生解**：如果不考虑人手敲代码累不累，这个问题在**底层系统、数学几何或关系代数上最纯粹、最直接的原生解法**是什么？
   - **追求形式化确定性**：严苛的编译器与强类型契约对人是负担，对 Agent 却是**免费的实时强化学习反馈护栏**——永远优先选择编译期最严格、状态最显式的技术栈（如显式 `<svg viewBox>` 数学坐标优于隐式 CSS 盲猜，强类型编译器优于动态弱类型）。
2. **零依赖专属实现优于黑盒库（Bespoke Native over Dependency Bloat）**：
   - 若某个需求仅需一个巨型第三方库 5% 的能力，且用标准库/原生 API 可在 100~200 行内写出纯数学或纯逻辑实现，**直接编写零依赖原生代码**，拒绝引入不可控的黑盒依赖。
3. **跨端共享契约，而非共享臃肿运行时（Contract Once, Native Everywhere）**：
   - 跨平台复用的核心是 `PRODUCT.md`（业务规则）与 `schema`（数据契约），表现层优先用各端物理上限最高的原生方案生成，不迁就笨重的跨端桥接层；复杂 UI 保持“原型即生产（Prototype-as-Production）”，严禁转入生产时偷懒降级。
4. **内部删除优于兼容**：
   - 单一场景直接实现，第二个真实用例出现时再抽象；内部重构直接删除废弃代码与旧路径，不堆砌内部兼容层（对外公开协议除外）。

## 停止与升级规则（人机边界）

遇到以下任一情况，立即停止自主修改并交由人裁定：
1. **改变对外承诺**：需缩减功能范围、修改公开 API 契约、变更持久化数据格式或降低性能/安全指标；
2. **不可逆操作风险**：涉及删除生产数据、触发外部真实账单、执行无回滚路径的部署或覆盖无备份原件；
3. **外部高危输入**：审查外部代码/PR 时发现触碰 CI 配置、构建脚本、新增未知外联网络、读写凭证或引入混淆二进制；
4. **局部补丁死循环**：对同一问题连续两次修复均告失败，或发现既有架构存在根本性冲突；
5. **价值判断权衡**：需要在用户体验、安全边界与研发成本之间做业务取舍。

## 验收清单

- [ ] 修改范围最小化，未顺手改动无关代码或静默篡改契约
- [ ] 同类缺陷位置已全局排查并同步修复
- [ ] 已运行对应层级的真实检查命令，且明确区分了“真实环境验证”与“Mock 验证”
- [ ] 若改变了文档化的架构契约或接口，已在同一变更中同步更新对应文档
- [ ] 未运行或受环境限制无法覆盖的验证项已显式列出，无隐瞒或伪装完成
