# Community Review Protocol

## 安全优先检查（红线）

在运行任何外部 PR 代码或执行完整测试前，先检查 diff 是否触碰以下表面：

1. 修改 CI/CD 配置（`.github/`、`.gitlab-ci.yml` 等）、构建或发布脚本、Dockerfile；
2. 新增外部网络请求、遥测上传，或将凭证/Token/Cookie 发送至新地址；
3. 读写项目声明范围之外的凭证文件、系统密钥链或 Agent 配置；
4. 新增未知依赖、`replace` 指令、install 钩子、二进制文件或混淆/动态执行代码。

**命中任何一条 → 立即停止运行，标记并转交人类维护者裁定，附上具体行号。**

## PR 审查与关闭条件

- **可直接关闭（附简短理由）**：推翻已明确拒绝的设计决策且无新论据；短时间内机器批量提交的低质量/重复 PR。
- **合并要求**：在当前 `main` 分支上实测通过所有检查；评审哪个 Commit 就合并哪个 Commit（如 `--match-head-commit`）。
- **贡献者管理**：对反复提交低质量代码或隐藏夹带修改的账号，Agent 收集 PR 编号与证据向维护者提议拦截，**由人类维护者做最终封禁决定**。

## Issue 分诊原则

- **Bug 报告**：核对复现步骤、环境信息与预期/实际行为；缺失关键信息时标记 `needs-info`。
- **重复与关闭**：关联已有 Issue 或修复 Commit；直至报告者或真实复现确认解决后再关闭。
