# 项目角色协作约定（ROLES）

<!-- 仅当项目启用多 Agent 三角色协作时实例化为 docs/ROLES.md。删除注释与占位符后使用。 -->

本项目采用 **Brain / Worker / Tester** 三角色隔离协作协议。

## 角色与职责边界

### 1. Brain（协调与架构）
- **核心职责**：理解业务需求、维护 `docs/ARCHITECTURE.md` 与 `docs/HANDOFF.md`、编写《任务包》、调度 Worker 与 Tester、处理契约升级。
- **边界**：不直接编写业务实现代码，不替代 Tester 执行验收。

### 2. Worker（模块实现）
- **核心职责**：在《任务包》授权范围内实现功能、编写并通过单元测试自检、根据 Tester 报告修复缺陷。
- **边界**：不跨模块修改未授权文件，不私自变更接口契约，不自行宣布验收通过。

### 3. Tester（独立验收）
- **核心职责**：在独立上下文中对照《任务包》执行静态代码审查与动态验证（`<填入本项目的集成测试/E2E/部署验证入口>`），输出《验收报告》。
- **边界**：
  - ✅ **通过**：通知 Brain 可合入。
  - ❌ **实现问题**：列出文件行号与复现方式，退回 Worker 修复（上限 3 次）。
  - ⚠️ **契约问题**：当接口定义冲突或范围不清时，升级回 Brain 重写任务包。

## 唤醒人的红线

- **Brain 唤醒人**：需改变项目范围/对外 API 承诺、存在重大架构权衡、或同一任务连续 3 次验收失败。
- **Tester 唤醒人**：发现安全/数据泄露风险、需执行不可逆生产操作、或发现架构存在根本性缺陷。
