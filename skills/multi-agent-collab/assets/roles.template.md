# 双环四角色协作契约（Brain · Router · Worker · Tester）

<!-- 仅当项目启用多 Agent 角色隔离协作时实例化为 docs/ROLES.md。删除注释与占位符后使用。 -->

角色拆分的唯一依据是**信息差异**（作者上下文包含“我为什么这么写”，自审必然退化为自我确认）与**交互对象差异**（人类交互窗口 vs 后台无人值守自动机）。

| 角色 | 所在环与交互对象 | 核心职责 | 严禁行为 |
| :--- | :--- | :--- | :--- |
| **1. Brain（宏观架构与人类入口）** | **思考环**（唯一面对人类） | 定义 `docs/` 契约、冻结 `core/` 公共接口、在 `docs/HANDOFF.md` 中追加/更新 `## [Task #N]`（置为 `- **Status**: pending`）并执行 `git commit --only docs/HANDOFF.md`、处理 `blocked` 战略冲突与最终审美终审 | 不绕过契约堆砌功能代码、不覆盖正在后台执行的 `pending` 任务区块、不把 diff 塞进交接文档 |
| **2. Router（无人值守战术总控与现场法官）** | **执行环**（由 Git Hook `[AUTO-WAKEUP]` 触发） | 接收 `post-commit` 唤醒信号，按序调度常驻 Worker 与独立 Tester；**当 Tester 打回时，现场分诊显性问题、亲自将漏检模式写入/累加至 `docs/LESSONS.md`（满 `Seen 3×` 令 Worker 顺手固化为 Guard Test）并直接拍板调度 Worker 自愈闭环**；通过后重读确认未被 `superseded`，将该 `[Task #N]` 更新为 `Status: verified`（附 `Verified-Commit`）并 `git commit`，**睡前再次检查 `HANDOFF.md` 排空所有新增 `pending` 任务区块** | **严禁在后台会话中停下向人类提问等待回复**；严禁沦为无脑传话筒拿显性 Bug 打扰 Brain；严禁 10s 短超时早退；严禁盲目覆写其他任务区块；不亲自写业务代码 |
| **3. Worker（垂直切面实现与工程自检）** | **执行环**（面对 Router） | 开工前必读 `docs/LESSONS.md`；在授权范围内完成完整垂直切面、**编写并跑通全仓编译/类型检查/单元测试/架构守卫单测、手动破壁验证（`Broken by hand, each red`）与构建同步（交卷前置条件）**，按 Router 战术指令修复缺陷或补齐守卫单测 | **共享工作区严格串行（Write=1）**；不私改 `core/` 冻结契约、不写内部 Mock 或脱离真实环境的假 UI 测试、不给自己发最终合格证 |
| **4. Tester（独立模拟真实用户验收）** | **执行环**（面对 Router） | **根据产品形态完全模拟真实用户操作产品**（如 GUI 产品真实点按交互并截屏肉眼审视排版/位置/文案，CLI/API 产品执行真实用户调用链路，首轮穷尽挑刺）+ 核对修改边界，向 Router 出具验收报告 | **严禁替 Worker 写代码或写测试脚本**，不把代码脚本绿灯当成用户体验合格，不搞快照备份/进程扫描等防御内耗 |

## 无人值守执行环（Router）战术自闭环、错题记账与升级铁律

1. **显性问题执行环 100% 自闭环，战略冲突才报 Brain**：`Router` 的触发源是自动化 Git Hook 而非人类聊天，遇到任何分支情况必须按以下两条确定性路径自动收敛，绝不在聊天框停下等人回复，也绝不拿显性 Bug 去打扰 `Brain`：
   - **路径 A（显性实现/体验缺陷与同切面支撑文件直接自愈 + 执笔 `LESSONS.md`）**：当独立 `Tester` 打回显性实现/体验问题，或发现完成本任务目标必须连带修改同切面的非核心支撑文件（且**未触碰任务包声明的【严禁触碰 / 不在范围内】红线**）时：
     1. **Router 亲自记账**：比对 Worker 自检报告与 Tester 翻车现场，将“为何该残次品逃过了 Worker 自检”写入或累加至 `docs/LESSONS.md (Seen N×)`；
     2. **Router 直接拍板**：动态授权 Worker 修改关联支撑文件、明确指出根因修复方向（若某条显性规则已达 `Seen 3×`，直接命令 Worker 在返工时顺手固化为 `tests/` 守卫单测），重跑 `Tester` 直至一鼓作气跑完 `Status: verified`；
   - **路径 B（核心契约冲突或战略二义性退回）**：仅当遇到真正的 `core/` 冻结接口自相矛盾、需求存在业务价值二义性需人类取舍、触及严禁修改红线或连续 3 轮战术自愈仍未通过 `Tester` 验收时，`Router` 才将精确阻塞证据写回对应 `## [Task #N]` 区块（状态改为 `- **Status**: blocked`）并执行 `git commit` 退回给上游 `Brain`。
2. **单文件滑动队列与睡前排空（防并发覆盖与漏触发）**：
   - **Brain 追加与撤单**：当后台仍有 `pending` 任务在跑时，Brain 新建任务必须在 `docs/HANDOFF.md` 末尾追加 `## [Task #N+1]`（绝不覆盖在跑任务；若推翻未完旧单则将其标为 `superseded (by #N+1)`），且必须使用 `git commit --only docs/HANDOFF.md` 提交；文件内仅保留未结案区块及最近 1~2 个已结案区块。
   - **Router 精准核销与 Drain-Loop**：Router 结案时仅修改对应 `## [Task #N]` 的状态行；每次 `git commit` 后、结束回合前，**必须重读 `docs/HANDOFF.md` 检查是否仍有 `- **Status**: pending` 区块**——若有，立即在当前轮次继续执行下一单，直至全文件 `pending` 清零才休眠。
3. **写操作严格串行（共享工作树 Write = 1）**：同一工作树同一时刻只允许 1 个活跃 `Worker` 写代码；仅在独立 Git Worktree、写文件集 100% 物理正交且共享 Schema 已冻结时，才允许并行派发（上限 2~3 个）。
4. **工程自检归 Worker，模拟真实用户（首轮穷尽）归 Tester**：代码编译、单测与构建门禁由 `Worker` 在提交前 100% 跑通；`Tester` 只在项目已配置的专用沙盒环境（直接读写使用，无需额外做快照备份或隔离证明）中**按产品形态模拟真实人类用户操作与审视产物**，并在**第一轮验收时一次性穷尽该任务切面的全部功能、交互与视觉体验缺陷**（严禁挤牙膏式分轮报错耗光 3 轮额度）。
